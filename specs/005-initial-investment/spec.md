# Feature Specification: 初回投資額設定機能

**Feature Branch**: `005-initial-investment`
**Created**: 2025-11-19
**Status**: Implemented
**Last Updated**: 2025-11-19
**Input**: User description: "NISA シミュレーターに初回投資額を設定できるようにしたい"

## Intent（インテント）*(mandatory)*

### 目的
NISA シミュレーターに初回投資額（一括投資額）を設定できる機能を追加し、既存資産や一時金を活用した投資計画のシミュレーションを可能にする。

### 背景
多くの投資家は、退職金、ボーナス、既存の貯蓄などを元手に NISA 投資を開始する。現在のシミュレーターは月次積立のみを想定しているため、初回投資額を含めた現実的な投資計画のシミュレーションができない。初回投資額を考慮することで、より正確な資産予測と投資戦略の比較が可能になる。

### 期待される成果
- ユーザーは初回投資額を含めた投資計画を立てられるようになる
- より正確な資産予測により、投資判断の質が向上する
- 初期投資がある場合とない場合の比較により、最適な投資戦略を選択できる
- NISA 制度を最大限活用するための投資計画が立てられる

### 成功した未来の状態
この機能がリリースされ、成功した後、ユーザーは退職金やボーナスなどの一時金を活用した NISA 投資計画を簡単にシミュレートできるようになった。初回投資額と月次積立を組み合わせた柔軟な投資戦略を比較検討できるようになり、ユーザーの投資計画の精度が大幅に向上した。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 初回投資額の設定とシミュレーション反映 (Priority: P1)

ユーザーがシミュレーター画面で初回投資額を入力し、その金額がシミュレーション結果（元本、総資産額、グラフ）に正しく反映される。

**Why this priority**: これが本機能の核心であり、入力からシミュレーション結果の反映まで一貫した機能として提供することで初めてユーザーに価値を提供できる。入力だけでは意味がなく、結果への反映も入力がなければ動作しないため、両者は分離できない一つの機能である。

**Independent Test**: シミュレーター画面を開き、初回投資額に 100 万円を入力してシミュレーションを実行し、結果画面で元本と総資産額に初回投資額が含まれていることを確認することで独立してテスト可能。この機能だけで MVP として価値を提供できる。

**Acceptance Scenarios**:

**入力とバリデーション**:
1. **Given** シミュレーター画面を開いた時、**When** 初回投資額入力欄を確認した時、**Then** 入力欄が表示されており、金額を入力できる
2. **Given** 初回投資額入力欄がある時、**When** 正の数値を入力した時、**Then** 入力値が受け付けられ、表示される
3. **Given** 初回投資額入力欄がある時、**When** 負の数値を入力した時、**Then** エラーメッセージ「0 円以上の金額を入力してください」が表示される
4. **Given** 初回投資額入力欄がある時、**When** 数値以外を入力した時、**Then** エラーメッセージ「数値を入力してください」が表示される

**シミュレーション結果への反映**:
5. **Given** 初回投資額に 100 万円を入力した時、**When** シミュレーションを実行した時、**Then** 開始時点の資産額が 100 万円として表示される
6. **Given** 初回投資額 100 万円と月次積立 3 万円を設定した時、**When** 1 年後の資産をシミュレートした時、**Then** 元本は 100 万円 + 36 万円 = 136 万円として計算される
7. **Given** 初回投資額が未入力（空欄）の時、**When** シミュレーションを実行した時、**Then** 初回投資額は 0 円として扱われる
8. **Given** 初回投資額 100 万円、年利 5%、20 年を設定した時、**When** グラフを確認した時、**Then** 0 年目（開始時点）の元本と総資産額がともに 100 万円として表示される

---

### User Story 2 - 初回投資額のリセット (Priority: P3)

ユーザーが入力した初回投資額をクリアし、再設定できる。

**Why this priority**: 便利な機能だが、手動で値を削除して再入力することでも同じ結果が得られる。P1 の機能がなくても、入力フィールドを手動でクリアすることで代替可能なため、優先度は最も低い。User Story 3（万円単位）の方がユーザビリティへの影響が大きいため、P3 に設定。

**Independent Test**: 初回投資額を入力後、リセットボタンをクリックし、入力欄が空になることを確認することで独立してテスト可能。P1 が完了していれば、この機能を独立して追加できる。

**Acceptance Scenarios**:

1. **Given** 初回投資額に値が入力されている時、**When** リセットボタンまたはクリアボタンをクリックした時、**Then** 初回投資額入力欄が空になる

---

### User Story 3 - 万円単位での入力・表示 (Priority: P2)

ユーザーが金額を万円単位で入力・確認できるようにし、より直感的で読みやすいインターフェースを提供する。

**Why this priority**: ユーザビリティの大幅な改善。日本では投資金額を万円単位で話すことが一般的であり、万円単位での表示の方が桁数が少なく読みやすい。P1 が完了していれば独立して追加可能。

**Independent Test**: シミュレーター画面を開き、月次積立額に「3」（3 万円）、初回投資額に「100」（100 万円）を入力してシミュレーションを実行し、結果が万円単位で表示されることを確認することで独立してテスト可能。

**Acceptance Scenarios**:

**入力フィールド**:
1. **Given** シミュレーター画面を開いた時、**When** 入力フィールドのラベルを確認した時、**Then** 「毎月の積立額（万円）」「初回投資額（万円）」と表示されている
2. **Given** 月次積立額入力欄がある時、**When** 「3」を入力した時、**Then** 内部的には 30,000 円として保存される
3. **Given** 初回投資額入力欄がある時、**When** 「100」を入力した時、**Then** 内部的には 1,000,000 円として保存される

**結果表示**:
4. **Given** シミュレーション結果が表示されている時、**When** 総資産額を確認した時、**Then** 万円単位で表示される（例: 「1,233 万円」）
5. **Given** シミュレーション結果が表示されている時、**When** 元本合計を確認した時、**Then** 万円単位で表示される（例: 「820 万円」）
6. **Given** シミュレーション結果が表示されている時、**When** 運用益を確認した時、**Then** 万円単位で表示される（例: 「413 万円」）

**グラフ表示**:
7. **Given** グラフが表示されている時、**When** Y 軸のラベルを確認した時、**Then** 万円単位で表示される（例: 「500 万円」「1000 万円」）

**一貫性**:
8. **Given** すべての画面を確認した時、**When** 金額表示を確認した時、**Then** すべての画面で万円単位が使用されている（メインページ、比較ページ、税金比較ページ）

---

### Edge Cases

- 初回投資額に非常に大きな値（例: 1 億円以上）を入力した場合でも、システムは上限なく受け付ける。ユーザーが自由に入力できることで、様々な投資シナリオのシミュレーションが可能になる。
- 初回投資額と月次積立の合計が NISA の年間投資上限を超える場合でも、シミュレーターとして制度的な制約は考慮せず、自由に設定可能とする。これにより、理想的な投資計画や複数年にわたる投資戦略のシミュレーションが可能になる。
- 初回投資額を入力後、途中で変更した場合、「計算する」ボタンをクリックすることでシミュレーション結果が更新される（自動更新ではなく、明示的なアクションが必要）。
- 数値入力時に先頭の 0 を入力した場合（例: 0100）、自動的に正規化されて正しい数値（100）として扱われる。これにより、入力エラーを防ぎ、ユーザビリティを向上させる。
- 毎月の積立額は 0 円を許容する。これにより、初回投資額のみでのシミュレーション（一括投資のみ）が可能になる。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: システムは初回投資額を入力するための入力フィールドを提供しなければならない
- **FR-002**: システムは初回投資額として 0 円以上の数値のみを受け付けなければならない
- **FR-003**: システムは初回投資額が数値以外の場合、エラーメッセージを表示しなければならない
- **FR-004**: システムは初回投資額をシミュレーション計算の元本に含めなければならない
- **FR-005**: システムは初回投資額が未入力の場合、0 円として扱わなければならない
- **FR-006**: システムは初回投資額を資産推移グラフの開始時点の資産額として反映しなければならない
- **FR-007**: システムは初回投資額と月次積立額を合算して総元本を計算しなければならない
- **FR-008**: システムは毎月の積立額として 0 円を許容しなければならない（初回投資額のみのシミュレーションを可能にする）
- **FR-009**: システムは数値入力時に先頭の 0 を自動的に削除しなければならない（例: 0100 → 100）

### Key Entities

- **初回投資額（Initial Investment Amount）**: ユーザーが投資開始時に一括で投資する金額。0 円以上の数値。NISA シミュレーションにおいて、月次積立とは別に開始時点で投資される資金を表す。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: ユーザーは 30 秒以内に初回投資額を設定できる
- **SC-002**: 初回投資額を含むシミュレーション結果が正確に計算される（手動計算との誤差 0.1% 以内）
- **SC-003**: 90% のユーザーが初回投資額入力機能を説明なしで使用できる
- **SC-004**: 初回投資額の入力から結果表示までが 3 秒以内に完了する
