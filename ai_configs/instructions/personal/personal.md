# Personal AI Instructions for speckit-sample

## 重要事項

### ドキュメント継続改善の原則
**CRITICAL**: AI 使用時に発生した具体的なコードミス・実装エラー・テスト失敗などは、必ずこの personal.md に記録すること。

#### 更新対象となるミス例
- API の引数形式の間違い
- テストのモック設定の誤り
- プロジェクト固有のメソッド呼び出し方法の間違い
- 環境固有の実行方法の誤解
- 型定義の命名規則違反
- ファクトリの使用方法の間違い

#### 記録フォーマット
```markdown
### [カテゴリ名]
- **問題**: 発生したエラーの概要
- **原因**: 間違った実装内容
- **正解**: 正しい実装方法
- **例**: 具体的なコード例
```

この継続的な改善により、同じミスの反復を防ぎ、開発効率を向上させる。

## プロジェクト固有の理解

### アーキテクチャ概要
speckit-sample は Next.js ベースの NISA シミュレーターアプリケーションです。

#### 技術スタック
- **フロントエンド**: React 19 + Next.js 15.1.3
- **言語**: TypeScript 5.x
- **可視化**: Chart.js, react-chartjs-2
- **状態管理**: クライアントサイド state のみ（永続化なし）

## コーディング規約

このプロジェクトでは以下のコーディング規約を厳守すること:

### TypeScript
- 型定義を明示的に行う
- `any` 型の使用は避ける

### React
- 関数コンポーネントを使用
- Hooks を適切に使用

### ファイル末尾の改行
- 「No newline at end of file」にならないように必ずファイル末尾に改行を追加すること

## 開発フロー

### 新機能実装時
1. `/speckit.specify` で仕様を作成
2. `/speckit.plan` で技術計画を作成
3. `/speckit.tasks` でタスク分解
4. 実装（必要に応じて LLM を切り替え）
5. テスト作成

### 既存機能修正時
- 既存のコードスタイルに合わせる
- 影響範囲を確認してからリファクタリング

（AI-DLC ワークフローの詳細は ai_configs/instructions/general.md を参照）
